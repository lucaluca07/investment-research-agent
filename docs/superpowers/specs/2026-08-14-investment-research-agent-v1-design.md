# 个人投研 Agent V1 设计规格

日期：2026-08-14  
状态：已完成方案评审，等待书面规格复核  
项目：`investment-research-agent`

## 1. 产品定义

本项目是一个本地运行、单用户使用的个人投研工作台。它不是选股器、自动交易系统或单纯的报告生成器，而是一套以证据为基础、以变化为驱动、具有时间一致性的研究系统。

系统维护以下研究闭环：

> 事实 → 变化 → 研究问题 → 可证伪论点 → 支持与反方证据 → 市场定价验证 → 催化剂与失效条件 → 版本历史

系统负责采集、计算、组织证据和提出研究建议；用户保留最终判断权。系统不直接输出交易指令，也不将复杂研究压缩为一个不透明的股票评分。

### 1.1 核心问题

系统必须能够回答：

1. 行业和公司最近发生了哪些重要变化？
2. 当前投资论点有哪些证据支持或反驳？
3. 股价处于什么位置，市场是否已经反映这些变化？
4. 接下来应观察什么，什么情况会使论点失效？

### 1.2 V1 研究范围

V1 聚焦 AI 服务器相关的高端 PCB 产业链，持续追踪：

- 胜宏科技
- 生益科技
- 中国巨石
- 金安国纪
- 中钨高新

系统允许按需研究任意 A 股公司，但临时研究对象不会自动进入持续追踪池。将标的加入追踪池必须经用户确认。

## 2. 关键设计原则

1. **确定性计算与 Agent 推理解耦。** 指标、财务计算、版本和状态变更由代码执行；Agent 负责解释、调查和提出建议。
2. **事实与结论可追溯。** 关键结论必须关联原始来源、数据日期、发布时间和生成过程。
3. **时间一致性。** 区分事实发生时间、对外发布时间、系统获取时间和研究使用时间，避免未来信息污染历史判断。
4. **变化优先。** 日常输出关注相对既有状态的重大变化；无重要变化时明确报告无变化。
5. **反证优先。** 每个核心论点同时维护支持证据、反方证据和明确失效条件。
6. **渐进式数据策略。** V1 使用公开数据跑通，但所有数据源通过 Provider 接口隔离，后续可替换付费服务。
7. **行业能力模块化。** PCB、煤炭、有色等通过 Research Pack 扩展，不修改通用研究内核。

## 3. 总体架构

### 3.1 数据源层

数据源按领域拆分：

- 行情、基准指数与 ETF
- 公司行动与交易日历
- 公司公告与定期报告
- 财务、分部和运营数据
- 宏观、利率、汇率和商品价格
- 行业资料、政策、新闻和调研资料

每类数据通过统一 Provider 契约接入。业务逻辑只能依赖标准化数据结构，不能直接依赖某个公开网站或供应商字段。

### 3.2 存储层

- 原始文件与响应：按来源和获取批次归档，不可静默覆盖。
- Parquet：保存未复权 OHLCV、复权因子、交易状态及其他时序数据。
- DuckDB：保存实体、事实、指标元数据、事件、证据、论点、催化剂、研究运行和版本关系。
- 派生缓存：保存可重建指标，并记录公式版本和输入数据版本。

日线和周线为 V1 的标准行情粒度。分钟线和 Tick 数据不在 V1 范围。

### 3.3 确定性分析层

该层负责：

- 财务与分部变化计算
- 价格位置与技术指标
- 相对强弱与横截面对比
- 估值历史分位
- 市场与宏观状态
- 异常变化检测
- 历史评估与可重放计算

Agent 不自行计算这些指标，只读取带口径、日期和版本的结果。

### 3.4 通用研究内核

该层负责：

- 文档采集、解析和引用定位
- 事实抽取与去重
- 变化检测和事件归并
- 检索与证据关联
- 宏观 → 行业 → 公司传导关系
- 论点、反证、催化剂和版本管理
- 报告渲染、审计和数据质量

### 3.5 Research Packs

每个 Pack 包含：

1. Skill：研究方法、分析顺序、常见误区和输出规范。
2. YAML 配置：实体、产业链、指标、别名、来源、传导关系、阈值和验证周期。
3. 专用代码：仅实现无法通用化的采集和计算。

首批 Pack：

- `pcb`
- `technical-analysis`
- `position-analytics`
- `macro`
- `market-regime`

未来的 `coal` 和 `nonferrous` 复用同一内核，通过新增 Pack 扩展。

### 3.6 DeepSeek Harness 编排层

Harness 负责任务规划、角色协作和推理，不承担数据库、指标计算或无约束状态写入。

角色包括：

- Research Lead：拆解问题、选择角色、合并任务状态。
- Industry Analyst：研究产业链、供需、技术与竞争格局。
- Company Analyst：研究公司暴露、财务与经营变化。
- Technical Analyst：解释价格位置、技术状态和相对强弱。
- Macro Analyst：解释宏观与市场状态的传导。
- Skeptic：寻找矛盾证据、替代解释和数据缺口。
- Editor：合并结果，检查引用、时效和表达一致性。

所有写操作通过受约束工具完成，并遵守状态机和审批规则。

## 4. 领域数据模型

### 4.1 核心对象

- `Entity`：公司、行业、产品、材料、客户、竞争对手、指数和 ETF。
- `Document`：公告、财报、政策、新闻、纪要和行业资料。
- `Fact`：能够被来源验证的事实陈述。
- `Metric`：包含时间、单位、口径、来源和公式版本的数值。
- `Event`：业绩、扩产、涨价、政策、认证或技术变化等事件。
- `Evidence`：支持或反驳某个研究判断的事实、指标或文档片段。
- `Thesis`：可证伪论点及其状态、证据、置信度、催化剂和失效条件。
- `Catalyst`：未来应验证的时间点或事件。
- `ResearchRun`：一次研究任务的输入、步骤、工具调用、输出和错误。
- `Snapshot`：某交易日的价格、技术、估值和市场状态快照。
- `ReportVersion`：不可变报告版本及其输入、差异和修订关系。

### 4.2 时间与来源字段

每条事实、指标和证据至少记录：

- 关联实体
- 内容或数值
- 有效时间或报告期
- 对外发布时间
- 来源与原始定位
- 系统获取时间
- 可信等级
- 数据或解析器版本

### 4.3 论点状态机

状态为：

`draft → pending_approval → active → challenged → invalidated → closed`

Agent 可以创建草稿和提出状态变更建议，但以下操作必须由用户确认：

- 激活核心论点
- 将论点标记为失效或关闭
- 改变关键失效条件
- 对受挑战论点恢复有效状态

## 5. PCB Research Pack

### 5.1 产业链范围

- 上游：电子纱、电子布、铜箔、树脂及关键材料。
- 中游：覆铜板、高多层 PCB、HDI、相关加工耗材。
- 下游：AI 服务器、交换机和算力基础设施。

### 5.2 公司与产业链映射

- 中国巨石：电子纱、电子布相关上游暴露。
- 生益科技、金安国纪：覆铜板及相关材料。
- 胜宏科技：高端 PCB 制造及 AI 服务器相关需求。
- 中钨高新：PCB 微钻等加工耗材暴露，同时允许关联未来的有色金属 Pack。

### 5.3 首批研究维度

- AI 服务器和交换机资本开支
- PCB 层数、材料等级和产品结构升级
- 产能、产能利用率、良率和客户认证
- 原材料价格与成本传导
- 产品价格、订单、收入和毛利变化
- 竞争格局、扩产节奏和供需错配
- 预期变化如何传导至盈利与估值

## 6. 研究工作流

### 6.1 每日追踪

收盘后执行：

1. 更新行情、基准、宏观和行业数据。
2. 执行交易日、复权、缺失和冲突检查。
3. 计算位置、技术状态、相对强弱、波动和异常。
4. 拉取追踪池公告、新闻和行业变化。
5. 由确定性程序生成变化候选并去重。
6. Agent 判断变化对产业链、公司和既有论点的影响。
7. Skeptic 寻找反方证据、替代解释和缺口。
8. 生成每日变化雷达；重大变化形成待审批的论点修订建议。

没有重大变化时，输出“未发现重大变化”，不生成填充性内容。

### 6.2 每周深度复盘

每周更新：

- 行业与公司核心指标变化
- 公司相对行业和市场的强弱
- 支持与反方证据
- 论点状态和失效条件
- 催化剂兑现、推迟或落空情况
- 市场表现对基本面判断的验证
- 下一周期最需要验证的问题

周报是不可变研究快照，不替代持续更新的行业和公司档案。

### 6.3 即时研究

用户可针对任意行业或公司发起问题。Research Lead 按需调用专业角色，优先复用已有证据，只对缺口发起新检索。

输出必须区分：

- 已确认事实
- 基于事实的推断
- 尚待验证的假设
- 当前无法获得的数据

即时研究对象只有经用户确认后才能加入持续追踪池。

## 7. 周报与版本机制

周报版本采用 `主题-周期-vN` 标识，例如 `PCB-Weekly-2026-W33-v1`。

每个版本记录：

- 数据截止时间和生成时间
- 输入数据源、数据版本和公式版本
- 新增、修改和撤销的事实
- 论点在周期起止时的状态差异
- 新增支持证据和反方证据
- 催化剂状态变化
- Agent 运行记录和人工审批记录
- 与上一版本的结构化差异

已发布版本不可修改。纠错或历史数据修订通过新版本完成，并明确说明改变的数据及其对原判断的影响。活态档案展示最新状态，同时保留完整变更历史。

## 8. 价格、技术与市场状态

### 8.1 多维位置模型

每个标的分别展示：

- 距离 52 周最低价和最高价的幅度
- 52 周区间位置
- 1 年、3 年、5 年价格历史分位
- 均线趋势和偏离程度
- RSI、MACD、KDJ、布林带等透明技术状态
- 成交量、波动率和流动性状态
- 相对行业、指数和竞争对手的强弱
- 个股估值历史分位

ETF 不套用个股估值模型。所有指标显示数据日期、复权方式、公式版本和组件值。

系统输出结构化状态和冲突解释，不将价格低位、技术超卖、估值便宜或基本面见底视为同一概念，也不直接翻译为交易指令。

### 8.2 市场与宏观状态

市场状态面板覆盖：

- 市场宽度、成交额、波动和风险偏好
- 利率、汇率、信用和主要商品价格
- 主要指数、行业轮动和相对强弱
- 宏观变量对经营、估值或二者的影响路径
- 当前环境对既有论点的支持、压制或中性状态

基本面、技术价格和宏观市场三条分析链保持独立，在论点层汇合，不合成为单一股票评分。

## 9. 用户界面与产物

V1 提供本地 Web 工作台和自然语言研究入口，包含：

1. **每日变化雷达**：重要变化、异常程度、影响对象、证据和待研究问题。
2. **PCB 行业驾驶舱**：产业链、趋势指标、公司映射、事件和行业论点。
3. **个股研究档案**：公司暴露、财务变化、证据、价格位置、估值和论点。
4. **价格与位置页面**：K 线、多周期位置、相对强弱、技术状态和计算解释。
5. **论点看板**：按状态管理论点、证据、反证和失效条件。
6. **催化剂与验证日历**：未来验证节点和完成状态。
7. **周报与版本中心**：不可变周报、修订版、差异和证据快照。
8. **自然语言研究入口**：发起即时研究，并选择性沉淀研究对象。

## 10. 数据可靠性与降级

### 10.1 Provider 记录

每次采集保存来源、请求参数、获取时间、原始响应、适用日期、发布时间、Provider 版本、解析器版本和质量状态。

### 10.2 数据质量检查

- 交易日完整性
- 价格和成交量异常
- 复权因子与公司行动一致性
- 财务单位、币种和报告期一致性
- 多来源冲突
- 文档发布时间与事实时间关系
- 数据新鲜度

### 10.3 降级规则

- 主源失败时切换备用源并记录切换。
- 多来源冲突时保存全部版本并标记冲突。
- 部分指标缺失时输出可完成部分，并说明影响。
- 行情未更新时暂停依赖当日价格的判断，显示上次快照日期。
- Agent 失败时保留检查点，从失败节点重试。
- 无法读取正文时不据此形成事实。
- 证据不足时输出“无法判断”。

每日任务必须幂等。原始数据、标准化数据、派生指标和研究结论分层存储，派生结果可根据输入及公式版本重建。

## 11. 测试策略

### 11.1 单元测试

覆盖复权、价格位置、技术指标、估值分位、相对强弱、时间有效性、单位换算、去重、版本生成、论点状态机和 Pack 配置校验。

### 11.2 Provider 契约测试

所有 Provider 必须输出统一结构。解析器使用固定样本测试，以便外部接口变化时快速失败并报告。

### 11.3 数据质量测试

覆盖缺失交易日、停牌、分红送转、负估值、异常成交量、财务口径变化、重复公告和来源冲突。

### 11.4 Agent 评测

固定案例检查 Agent 是否：

- 区分事实、推断和假设
- 为重要结论提供来源
- 主动寻找反方证据
- 避免自行计算确定性指标
- 遵守状态变更权限
- 在相同证据下保持核心结论稳定

### 11.5 端到端测试

验证完整链路：

> 变化检测 → 深度研究 → 证据入库 → 论点建议 → 人工确认 → 页面和周报版本

## 12. V1 验收标准

V1 必须满足：

1. PCB 核心池连续更新 20 个交易日，不重复事件、不破坏历史快照。
2. 能解释五家公司当前价格位置及不同维度之间的冲突。
3. 财报发布后能识别关键变化并关联已有论点。
4. 行业材料价格或 AI 服务器需求变化时能展示传导路径。
5. 每期周报具有不可变版本，并能与上一期做结构化差异比较。
6. 数据源失败时能够降级、标记影响范围并恢复。
7. 即时研究陌生公司时不污染持续追踪池。
8. 未经用户确认，Agent 不能激活、反转或关闭核心论点。
9. 关键结论能追溯到原始证据、数据日期和研究过程。

## 13. V1 范围边界

### 13.1 包含

- 本地单用户 Web 工作台
- DeepSeek Harness 编排
- PCB Research Pack
- 五家公司持续追踪
- 任意 A 股公司的即时研究
- 日线和周线行情本地存储
- 技术位置、估值位置和相对强弱
- 每日变化雷达和版本化每周复盘
- 证据、论点、催化剂和人工审批
- 免费数据源及可替换 Provider 接口

### 13.2 不包含

- 自动交易和组合下单
- 分钟级或 Tick 行情
- 全市场量化选股
- 多用户权限和云端协作
- 移动端应用
- 煤炭、有色的完整 Research Pack
- 复杂组合优化和收益归因
- 付费数据库的正式接入

## 14. 实施约束

第一轮实施应形成一个完整的 PCB 垂直切片，而不是同时铺开所有页面和数据源。建议按以下依赖顺序规划：

> 行情与存储 → 位置计算 → 证据与论点模型 → PCB Pack → Harness 工作流 → Web 工作台 → 定时追踪

旧项目 `ai-stock` 保持不变。新项目可以参考其数据校验、证据存储和测试经验，但不复制其整体架构或历史复杂度。
